# 产品需求文档（PRD）

## 1. 背景、目标与非目标

现有脚本已从 Amazon Progress Tracker 的 `.pt-delivery-card-trackingId` 保守读取物流号，并只在商品可唯一匹配时计算包裹金额。历史版本曾出现 `SEE` 尾缀误识别、订单错配和金额错误；当前结果也缺少可视化复核与报单工作台。

**目标**：让用户从 Amazon 订单页得到可追溯、可复核的包裹记录，集中处理异常，并以复制/导出的方式辅助在购买组平台报单。

**非目标**：

- 不替用户下单、退款、修改 Amazon 或购买组数据。
- 不把订单总额、税费或猜测值当作包裹商品金额。
- 不在未获平台公开契约和用户授权时自动向 BFMR/MOD 提交。
- 不承诺第三方承运商可查询所有 Amazon Tracking ID。

## 2. 用户与场景

| 用户 | 核心诉求 | 场景 |
| --- | --- | --- |
| 购买组参与者 | 快速且正确地报送 tracking | 多笔 Amazon 订单拆成多个包裹，需在截止前提交。 |
| 重度用户 | 发现遗漏、拒绝与支付差异 | 每天批量提取，优先处理未报单、失败、长期无更新的包裹。 |
| 谨慎用户 | 对金额/关联关系有证据 | 遇到合包、同款多件或页面变动时，宁可人工确认也不误报。 |

## 3. 用户故事

1. 作为用户，我要一键读取当前加载的 Amazon 订单的包裹物流号，以便避免逐页抄写。
2. 作为用户，我要看到每个 tracking 关联的订单、商品金额状态及证据来源，以便确认是否可报。
3. 作为用户，我要按“待复核/待报单/已报单/失败”筛选，以便先处理风险最高的记录。
4. 作为用户，我要预览并复制/下载平台所需列，以便在没有 API 时仍可完成正常的人工报单。
5. 作为用户，我要能够编辑本地备注和报单状态，但不能意外篡改原始提取证据。

## 4. 功能范围与优先级

| 优先级 | 功能 | 验收要点 |
| --- | --- | --- |
| P0 | 可信提取 | 只采纳指定 DOM 字段；TBA 且严格末尾 `SEE` 才去尾；保留原值和来源。 |
| P0 | 包裹工作台 | 表格展示 tracking、订单、金额状态、提取时间、报单状态；支持搜索、筛选、排序。 |
| P0 | 异常与复核 | 缺号、请求失败、关联不唯一、金额待识别均有原因和人工操作入口。 |
| P0 | 复制/导出 | 预览字段、复制 TSV、下载 UTF-8 CSV；只导出用户选中的记录。 |
| P0 | 本地持久化 | 数据默认仅在浏览器本地保存，可清空/导出。 |
| P1 | 平台映射 | BFMR 或用户自定义模板仅在字段经用户确认后保存；输出不可暗示已提交。 |
| P1 | 追踪状态接入 | 通过用户自备、获授权的追踪服务显示状态/最后事件；失败可回退。 |
| P2 | 官方平台连接器 | 仅在取得公开 API、权限范围、幂等与错误语义后开发。 |

## 5. 业务规则与异常

- 主键为标准化 tracking；同号的多次提取合并，但每次提取保留证据快照和时间。
- `TBA<数字>SEE` 仅去掉末尾 `SEE`；其他任何以 SEE 结尾的号码不得修改。
- 订单关联优先级：包裹页中明确的订单详情链接 > 包裹页可见订单号 > 发起订单卡的 fallback。后两者标注较低置信度；冲突时不自动选一个。
- 金额仅在包裹商品与订单商品按 ASIN（其次图像键）唯一匹配，且商品级价格明确、数量不超出时标为“已确认”；否则为“待识别”。
- 获取失败、DOM 缺失、登录失效、限流、解析异常均不得静默丢弃：在运行摘要和异常队列显示 URL（脱敏）、错误类别和重试建议。
- “已报单”只是用户本地标记；只有未来官方连接器收到可验证成功响应时，才显示“平台已确认”。

## 6. 指标

本地匿名聚合、默认关闭遥测；启用后只记录计数和耗时：提取尝试/成功率、有效 tracking 率、待识别金额率、关联冲突率、异常关闭率、导出次数、从提取到本地标记已报单的时长。不得采集完整订单号、tracking、地址、商品名或平台 token。

## 7. 验收标准

- 给定含 `TBA123SEE` 和非 TBA `1Z...SEE` 的 fixture，分别产出 `TBA123` 和原字符串。
- 一单多包裹和一包裹多订单均保留完整关系；冲突记录进入待复核而非错配。
- 金额缺失、重复匹配、数量冲突时显示待识别，不能用订单总额替代。
- 选中记录导出的字段、顺序、CSV 转义与预览完全一致；未选中和待复核记录按用户选择处理并有警告。
- 断网、401/429、页面缺字段后界面可恢复，并保留未受影响的结果。
- 清空本地数据后刷新页面不再可见历史记录；导出不含 token 和 Amazon 地址。

## 8. 路线图与风险

| 阶段 | 内容 | 主要风险与缓解 |
| --- | --- | --- |
| 0：验证 | 收集经用户脱敏的页面 fixture，覆盖历史三类错误 | Amazon DOM 变化；选择器适配分层、fixture 回归。 |
| 1：MVP | 提取、工作台、异常队列、本地存储、TSV/CSV | 大批量请求/登录过期；并发限制、取消、重试和进度。 |
| 2：可选追踪 | 接入用户授权的追踪服务 | 费用、覆盖率、TBA 可用性；服务可插拔并标示来源。 |
| 3：平台连接 | BFMR/MOD 官方文档验证后的连接器 | 未公开 API、字段/政策变化；独立授权、幂等、人工回退。 |

最大的产品风险是把“提取成功”误当“报单成功”。产品必须将两种状态分离，并将不确定性显式呈现。
