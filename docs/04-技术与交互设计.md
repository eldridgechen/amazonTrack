# 技术与交互设计

## 1. 信息架构与关键交互

```text
悬浮入口「提取」
  └─ 提取进度 / 运行摘要
       └─ 物流工作台
            ├─ 全部包裹（搜索、筛选、排序、批量选择）
            ├─ 待复核（缺号、关联冲突、金额待识别、请求失败）
            ├─ 报单准备（字段映射预览、复制 TSV、导出 CSV）
            └─ 设置（本地数据、导出/清空、追踪服务、隐私）
```

- **提取**：先显示扫描数量、成功/异常/跳过数和取消按钮；完成后进入工作台，而不是仅输出 textarea。
- **行详情抽屉**：显示标准化 tracking、原始文本、抓取 URL/时间、订单关系及置信度、商品匹配结果、错误历史；原始证据只读。
- **待复核**：用户可确认/拆分关联、增加备注、将记录排除出导出；对金额只允许标“用户确认”，不覆盖计算值。
- **报单准备**：先选平台“自定义/BFMR（待字段确认）/MOD（待识别）”，再选择列；展示“这是导出，尚未提交到平台”的固定提示。复制为 TSV，下载为 CSV；导出成功不自动改“已报单”。
- **状态流**：`已提取 → 待复核 | 待报单 → 已报单（本地） | 报单失败（本地）`；“平台已确认”只供未来官方连接器使用。

## 2. 数据模型

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| Package | `id`, `trackingNormalized`, `trackingRaw`, `carrier`, `extractionStatus`, `createdAt`, `updatedAt` | `id` 用内部 UUID，避免 tracking 变更破坏审计。 |
| OrderLink | `packageId`, `orderId`, `source`, `confidence`, `state` | `source`: explicit-link/page-text/fallback；一对多。 |
| ItemMatch | `packageId`, `identityType`, `identity`, `packageQty`, `orderQty`, `unitPrice`, `amount`, `state` | 保留每个匹配项，避免只有总额而无来源。 |
| Evidence | `packageId`, `sourceUrlRedacted`, `selector`, `rawValue`, `capturedAt`, `parserVersion` | 原始证据可审计；URL 不含敏感 query。 |
| Submission | `packageId`, `target`, `mappingVersion`, `localState`, `externalReference?`, `attemptedAt`, `error?` | `externalReference` 仅由获授权连接器填写。 |
| ExtractionRun | `id`, `startedAt`, `finishedAt`, `counts`, `errors` | 支持运行摘要与诊断。 |

实现路线为两步：当前 userscript MVP 用同源 `localStorage` 只保存本地报单状态和更新时间，导出使用临时内存 Blob；包裹证据与运行历史需要持久化时迁移到 IndexedDB。保留期默认由用户控制，后续提供“一键清空所有本地数据”。

## 3. 模块边界与数据流

```text
Amazon 已登录 DOM
  → LinkDiscovery（同源 URL 白名单）
  → FetchScheduler（限并发、取消、退避）
  → Parser（tracking / 订单 / 商品）
  → Validator & Reconciler（置信度、冲突、金额）
  → Repository（IndexedDB + 证据）
  → Workbench UI（复核 / 筛选 / 导出）
  → ExportAdapter（TSV / CSV）
  └─ 可选 TrackingProvider / PlatformConnector（明确授权后）
```

- **Parser** 不读写存储、不提交外站；所有纯函数应能在 fixture 中单测。
- **Validator & Reconciler** 产生状态和原因，禁止“猜测修复”。
- **PlatformConnector** 必须隔离于 userscript 的核心提取链路，具备授权 UI、字段契约、幂等键、审计日志与禁用开关。
- 现有项目为单 userscript；MVP 可按上述模块拆分为单文件内的命名模块，待测试增长后再打包构建，不引入服务器。

## 4. Amazon 提取与可靠性设计

1. 仅处理当前 Amazon 同源、用户已登录状态下发现的 Track Package/Progress Tracker 链接，拒绝跨域 URL。
2. `trackingFromDeliveryCard` 只读取 `.pt-delivery-card-trackingId`；记录选择器和原文。找不到即 `missing_tracking_field`，不可从 URL、页面其他文本或订单号猜号。
3. 规范化仅适用于严格正则 `^(TBA\\d+)SEE$`。所有其他格式原样保留（空白折叠、大小写统一可单独记录）。
4. 使用订单详情明确链接形成关系；仅页面文本或订单卡 fallback 的关联以较低置信度显示。多个高置信候选或相互冲突时 `needs_review`。
5. 商品金额要求 ASIN 优先、图像键兜底的唯一匹配、明确商品级单价、可兼容数量；税、运费、促销和订单总价永不参与。
6. 请求调度默认低并发（建议 2）、可取消；对 429/5xx 指数退避且限制次数，对 401/登录页停止并提示用户刷新登录。每个失败保存在 Run 中。
7. 对 Amazon 页面版本实施 fixture 回归：最小成功页、无 tracking、TBA+SEE、非 TBA+SEE、一单多包裹、一包多单、重复商品、缺价、限流/登录失效。

## 5. BFMR/MOD 集成策略

| 模式 | 当前状态 | 设计 |
| --- | --- | --- |
| 导出与手工报单 | 可实施 | 用户选择字段，预览、复制 TSV 或下载 CSV；平台网页由用户自行操作。 |
| BFMR 官方同步 | 有公开扩展存在，但本项目无已验证写入契约 | 不读取其 token、不调用其私有接口。仅在 BFMR 提供书面 API/授权文档后开发独立连接器。 |
| MOD 直连 | 未确认目标平台/接口 | 仅提供“自定义导出”；收集域名、字段模板、官方文档后再决策。 |
| 通用连接器 | 未来 | OAuth/API token 存于浏览器扩展安全存储，最小权限、明确 consent、连接可撤销；每次提交使用幂等键并回显服务器响应。 |

## 6. 隐私与安全

- 默认零外发：Amazon 页面数据仅处理并保存于用户浏览器本地。
- 不收集 Amazon 登录凭据、支付信息、地址；不要在日志、遥测、导出文件名或错误上报中留下它们。
- 将订单号、tracking、商品和金额视为敏感经营数据：UI 遮罩、复制前提示、导出前说明目的地；支持清空。
- CSP/DOM 安全：不把 Amazon 文本直接插进 `innerHTML`；改用 `textContent` 建立 UI，防止页面文本触发脚本注入。
- 连接器只允许 HTTPS 固定域名、最小权限 token、短生命周期/可撤销凭据；禁止把 token 写入 CSV、console 或诊断包。

## 7. 测试与质量门禁

- 单元：规范化、字段提取、订单优先级、金额唯一匹配、CSV 转义、状态机。
- Fixture 集成：模拟 DOM 和 fetch 成功/失败路径，断言证据与 UI 状态。
- 手工：真实 Amazon 测试账户下抽样逐项核对，不把页面快照提交到仓库；确认导出后平台仍需由用户核验。
- 静态：`node --check`、现有解析测试；引入构建工具后增加 lint 和依赖审计。

## 8. 实施决策记录

当前脚本使用 `innerHTML` 渲染从 Amazon 文本派生的结果。按本设计实施工作台时应优先改为 DOM API + `textContent`，这是安全修复，不改变提取规则。该变更应配合 UI fixture 测试单独提交。
