# 竞品与工作流调研

调研日期：2026-11-01。本文只依据公开资料与当前仓库代码；页面、定价、能力会变化。

## 证据分级

- **已验证**：一手公开产品页、帮助中心或 API 文档直接说明。
- **推断**：从已验证能力推导出的产品设计方向，不代表第三方承诺。
- **待确认**：影响是否自动提交或字段映射的关键信息，须由用户或平台文档确认。

## 推断：建议的报单工作流

1. 用户在已登录的 Amazon 订单页主动点击提取。
2. 工具按包裹建立本地记录，展示物流号、关联订单、金额可信度和提取证据。
3. 用户先处理“缺物流号、关联不唯一、金额待识别、已过期/待确认”等异常。
4. 用户选择平台预设或自定义列映射，预览后复制表格/下载 CSV（首发）。
5. 用户在 BFMR/MOD 的正常网页流程中粘贴或上传，并在本工具标记“已报单/失败/待复核”。
6. 有平台官方 API、字段契约和用户令牌时，才提供独立的授权连接器与幂等提交。

这是基于上述公开产品模式的设计推断，不表示 BFMR 或“MOD”当前接受 CSV、粘贴或批量导入。

## 待确认清单

| 主题 | 必须确认的问题 | 未确认前的处理 |
| --- | --- | --- |
| MOD 的身份 | “MOD”具体是哪个域名、产品、用户账号类型？ | 不建立品牌预设，不写任何直连代码。 |
| BFMR 写入方式 | 用户的 BFMR 账户是否提供公开 API、OAuth/API token 申请说明、CSV 导入或固定表单字段？ | 只做用户本地导出/复制；不自动发送。 |
| 报单字段 | 是否需要订单号、商品/数量、单价、tracking、承运商、日期、截图、预约/Deal ID？一单多包裹如何提交？ | 用可配置映射，默认不把金额作为必填报单字段。 |
| 规则 | 截止时间、允许的承运商、tracking 可更换规则、拒绝原因和重试限制？ | 将“状态”视为本地备注，禁止声称成功。 |
| 隐私与授权 | 平台是否允许浏览器扩展读取 Amazon 页面并发送订单数据？ | 默认不上传、只存本地；用户主动导出。 |

## 结论

首期的差异化不是复制第三方全自动同步，而是把 Amazon 页面中容易错的“包裹—物流号—订单—金额证据”做成可审计队列，并提供不依赖未证实接口的报单辅助。拿到 BFMR/MOD 的官方接入材料后，再进入集成验证阶段。
